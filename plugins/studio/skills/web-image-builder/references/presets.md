# 用途別プリセットとレイアウト選択

## 寸法一覧

| preset | 寸法 | 主な用途 | 備考 |
|---|---|---|---|
| `ogp` | 1200×630 | Open Graph 標準 | Facebook / Slack / LINE / はてな等。比率 1.905:1 |
| `x-card` | 1200×675 | X の summary_large_image | 16:9。OGPと兼用も可だが上下が切られることがある |
| `linkedin` | 1200×627 | LinkedIn 共有 | 実質OGPと同じ扱いで良い |
| `slider` | 1920×1080 | サイト内ヒーロー / スライダー | 16:9。PCファーストのファーストビュー |
| `slider-wide` | 2400×1000 | ワイドなヒーロー帯 | 2.4:1。フルブリードの帯に使う |
| `banner` | 1200×300 | 記事内・サイドの横長バナー | `strip` レイアウトが効く |
| `banner-mpu` | 300×250 | レクタングル広告 | 情報を1つに絞る。タイトル＋CTAのみ |
| `leaderboard` | 728×90 | 細長バナー | 比率8:1。`strip` 一列でしか成立しない |
| `square` | 1080×1080 | Instagram フィード / 汎用SNS | |
| `story` | 1080×1920 | Stories / Reels / LINE VOOM | 上下に UI が重なるので端に文字を置かない |
| `thumbnail` | 1280×720 | YouTube サムネイル | 一覧では 320×180 程度に縮小表示される |

一覧に無い寸法は `--size 1600x900` のように直接渡す。

## 実際にユーザーが見るサイズは、作ったサイズより小さい

ここを外すと「作ったときは読めたのに、投稿したら読めない」が起きる。

| 掲載面 | 実際の表示幅の目安 | 作成サイズに対する比率 |
|---|---|---|
| X のタイムライン | 約 500px | 40% |
| Slack のリンク展開 | 約 360px | 30% |
| LINE のトークプレビュー | 約 300px | 25% |
| YouTube の関連動画一覧 | 約 168px | 13% |

つまり **1200px 幅で作った画像の文字は、最悪 1/4 に縮んで表示される**。
主要コピーは実寸で40px以上を確保する。1200×630で 40px は、Slack上では約12px相当になる。
それ以下の補足情報（日付、カテゴリ）は読めなくても成立するように配置する。

対策として解像度を上げるのは無効。縮小表示は**表示側**で起きるので、
`--scale 2` で 2400×1260 にしても、Slack はやはり 360px に縮める。
効くのは**文字を大きくすること**だけ。

ここで言っているのは**判読性**の軸（文字が小さすぎて読めない）。
**鮮明さ**の軸（画素数が表示に足りず滲む）は別問題で、そちらは解像度を上げれば直る。
判断基準は SKILL.md の「解像度が足りているか確認する」を見ること。
SNSのリンク展開は表示枠が小さいので1200pxで足りるが、
サイト全幅のヒーローは1920pxでは足りない。

## レイアウトの選び方

`--layout` を省略すると縦横比から自動で選ばれる。意図的に変えたいときだけ指定する。

- **`standard`**（比率 1.15〜3.0）
  ロゴ／バッジを上、タイトルを中央、メタ情報とアクセントバーを下に置く左揃えの構成。
  OGP、スライダー、サムネイルの既定。情報が3層あるものに向く。

- **`centered`**（比率 1.15以下 = 正方形・縦長）
  すべて中央揃え。要素が中央に寄って固まるので、縦に長いキャンバスでも間延びしない。
  Instagram、Stories、レクタングル広告向け。

- **`strip`**（比率 3.0以上 = 極端な横長）
  ロゴ｜テキスト｜CTA の横一列。縦の余白が無い帯では、これ以外の構成は成立しない。
  `leaderboard`、細い `banner` 向け。

## 縦長・小サイズでの注意

- `story` は上下 15% 程度にプラットフォームのUI（ユーザー名、リアクション）が重なる。
  重要な要素をその帯に置かない。既定のパディングはこれを見込んである。
- `banner-mpu` や `leaderboard` のような小さいキャンバスでは、
  タイトルの文字サイズ係数が自動で上がる。面積が小さいほど相対的に大きい字でないと沈むため。
  それでも入る情報量は限られるので、**要素を減らす**方向で調整する。文字を小さくして詰め込まない。
