# ロゴロックアップ（横型 / 縦型）

`scripts/build_logo.py` で作る。他の画像とは3点で性質が逆なので別スクリプトにしてある。

1. **キャンバスを中身に合わせる**（他の画像は中身をキャンバスに合わせる）
2. **背景が透過**（どんな地色にも載る必要がある）
3. **SVGが主成果物**。ヘッダー・ヒーロー・フッターは全部Webなので、
   ラスタライズする理由が一つも無い

3点目が最も重要。ロゴをPNGで配ると、Retinaで滲む・任意サイズに追従できない・
地色を変えられない、の3つを同時に抱える。SVGなら全部解決する。
`build_logo.py` は文字を fontTools でアウトライン（パス）に変換するので、
**閲覧環境のフォント有無にも、Webフォントの読み込み待ちにも影響されない**。
デザイナーがロゴを「アウトライン化」して納品するのと同じ状態になる。
副次的に、フォントの埋め込み配布条項にも触れない。

## 2つの型

| 型 | 構成 | 主な用途 | 縦横比の目安 |
|---|---|---|---|
| `--layout h` | アイコン左＋テキスト右（＋タグライン） | ヘッダー、フッター | 3:1 〜 6:1 |
| `--layout v` | アイコン上＋タイトル下＋ルビ | ヒーローセクション | 1:1 〜 2.5:1 |

縦型の縦横比は**名前の長さで決まる**。日本語8文字＋ルビだと約2.1:1で、
名前としては縦積みだが形は横長になる。「縦型」は積み方の呼び名で、
縦長のシルエットになるとは限らない。短い名前なら1:1に近づく。

```bash
# 横型（ヘッダー用）
python3 scripts/build_logo.py --layout h \
  --icon icon.svg --icon-color "#c9a227" \
  --title "占星術アステリア" --font BrandSans-Bold.otf --color "#141414" \
  --height 40 --png-heights 40,80,120 --out dist/logo_h

# 縦型（ヒーロー用）
python3 scripts/build_logo.py --layout v \
  --icon icon.svg --icon-color "#e0be55" \
  --title "占星術アステリア" --ruby "A S T E R I A" \
  --font BrandSans-Bold.otf --color "#ffffff" \
  --height 140 --png-heights 140,280 --out dist/logo_v_rev
```

## 最適なサイズ

### 表示高さ（CSSでの指定値）

ロゴは幅ではなく**高さ**で運用する。幅は縦横比に任せる（`height: 32px; width: auto`）。

| 掲載面 | 推奨表示高さ | 備考 |
|---|---|---|
| PCヘッダー | **32px**（28〜40px） | 40pxを超えるとヘッダーが重くなる |
| モバイルヘッダー | **28px**（24〜32px） | タップ領域は44pxを別途確保する |
| フッター | **28px**（24〜32px） | ヘッダーより一段小さくすると締まる |
| PCヒーロー（縦型） | **120px**（96〜160px） | |
| モバイルヒーロー（縦型） | **88px**（72〜100px） | |

### 書き出しサイズ

**SVGを1枚配るのが正解。** 上のどの表示高さでも同じ1ファイルで足り、
DPRが1でも2でも3でも鮮明。以下のPNGは、SVGが使えない場面のためだけに用意する。

| 型 | 用途 | 書き出し高さ | 例（比5.4:1 / 2.1:1のとき） |
|---|---|---|---|
| 横型 | @1x | 40px | 217×40 |
| 横型 | @2x（Retina） | 80px | 434×80 |
| 横型 | @3x（高DPRのAndroid） | 120px | 651×120 |
| 縦型 | @1x | 140px | 295×140 |
| 縦型 | @2x | 280px | 590×280 |

PNGが必要になるのは、メール署名、古いCMS、印刷物、SNSのプロフィール画像、
Officeドキュメントあたり。Web本体では使わない。

### アイコン単体の派生（必ず要求されるので先に作る）

| 用途 | サイズ | 形式 |
|---|---|---|
| favicon | 32×32 | SVG（`icon.svg`）＋フォールバックのICO |
| apple-touch-icon | 180×180 | PNG（透過なし、余白込み） |
| PWA manifest | 192×192 / 512×512 | PNG |

apple-touch-icon は**透過を使えない**（iOSが黒く塗る）ので、背景色を敷いて書き出す。

## 運用上、必ず必要になるもの

**通常版と反転版の2セット。** 地色が変わるヘッダー（スクロールで透明→白など）や、
明るいページと暗いページが混在するサイトでは両方使う。
`--color` と `--icon-color` を変えて2回実行するだけ。

**最小使用サイズを決める。** 横型は高さ24px、縦型は72pxを下回ると
タグラインやルビが判読できなくなる。ブランドガイドに書いておくと事故が減る。

**クリアスペース（余白）。** `--pad` にロゴ高の比率で渡す。0.15〜0.25が目安。
既定は0（密着）で、CSS側で余白を取る前提。画像として単体配布するときは
`--pad 0.2` あたりを付けておくと、他人が詰めて配置する事故を防げる。

## 調整の勘所

`build_logo.py` の `DEFAULTS` に各要素の比率が入っている。すべて `--height` に対する倍率なので、
どの高さで出しても同じ見た目になる。触るとしたらこのあたり。

- `title_ratio_h`（既定0.52）— 横型のタイトルサイズ。ロゴ高に対する比。
  和文は0.50〜0.55、欧文だけなら0.60前後まで上げられる
- `gap_h`（既定0.26）— アイコンとテキストの間隔。詰めすぎると窮屈、
  空けすぎると2つの要素に見える
- `tracking_ruby`（既定0.055）— ルビの字間。欧文を広げて組むのが定石
- `icon_ratio_v`（既定0.46）— 縦型でアイコンが占める高さ

縦位置は**キャップハイト基準**で揃えている（フォントのボックス基準ではなく実際のインクの高さ）。
アイコンと文字の光学的な中心が合うのはこの基準のときなので、変更するときは注意。

## アイコンの色を上書きするとき

`--icon-color` は `<g>` に `fill` と `color` の両方を設定する。
単色アイコンは `fill="currentColor"` で書かれていることが多く、
`fill` 属性だけでは `currentColor` が解決されないため。
多色アイコンには使えないので、その場合は色ごとのSVGを用意する。
