# web-image-builder

## 2つの用途で入口が違う

- **ロゴロックアップ**（ヘッダー / ヒーロー / フッター）→ `scripts/build_logo.py`。
  透過SVGが主成果物。詳細は `references/logo.md` を読む。
  ロゴは「キャンバスを中身に合わせる・透過・ラスタライズしない」で、
  以下の話とは前提が逆なので混ぜないこと
- **それ以外の文字入り画像**（OGP / バナー / スライダー / SNS）→ `scripts/build_image.py`。
  以下の説明はこちら

文字入り画像で「文字が汚い・にじむ・□になる・切れる」が起きるのは、ほぼ全部**画像化の工程**が原因。
このスキルはその工程を1回だけ、正しい条件で通すためのもの。

## 中核となる考え方

> **劣化に弱いもの（文字・ロゴ）はブラウザにベクタで描かせ、劣化に強いもの（背景写真）だけをラスタで扱う。**

文字は輪郭の情報量が多く、少しの縮小や再圧縮で潰れる。背景写真は元々連続階調なので縮小に強い。
だから両者を同じ扱いにしてはいけない。この分離ができていれば、劣化ポイントは「背景の縮小」1箇所だけになる。

出力サイズと同じ寸法のビューポートでスクリーンショットを撮れば、拡大・縮小・再圧縮が一切入らない。
これが**等倍原則**で、このスキルで最も重要なルール。

## ワークフロー

### 1. 用途と寸法を決める

`--preset` で選ぶ。用途と寸法の対応、SNS側の表示縮小の事情は `references/presets.md` を読む。
一覧に無い寸法は `--size 1600x900` で直接指定できる。

複数サイズへ展開する案件（同じキャンペーンをOGP＋バナー＋スライダーで出すなど）は
最初から `--spec` のバッチで組む。`references/recipes.md` に書式がある。

### 2. 素材を揃える

必須と任意を分ける。**必須の素材が無い状態で作り始めないこと。**
ロゴと背景が欠けた画像は、どれだけ組版が正しくてもブランドの画像にならない。
`build_image.py` も `--logo` / `--bg` が無ければ警告を出す。

| 素材 | 区分 | 要件 | 理由 |
|---|---|---|---|
| **ロゴ** | **必須** | SVG（`--logo`） | PNGロゴは拡大でボケる。ベクタなら任意サイズで無劣化 |
| **背景** | **必須** | 出力より大きいラスタ画像（`--bg`） | `cover` で縮小クロップされる。拡大は絶対に避ける |
| フォント | 任意 | 日本語グリフを持つTTF/OTF/TTC（`--font`） | 未指定なら環境から自動検出。無ければエラーで停止する |
| キャッチコピー | 任意 | 1行（`--title`） | 画像が唯一運べる「何のサービスか」 |
| 装飾 | 任意 | 区切り装飾（`--divider`） | 間を作り視線を止める。意味は運ばせない |

自社フォントが `.ttc`（複数フェイスのコレクション）の場合だけ注意が必要。
先頭フェイスが使われるので、先頭が日本語フェイスでないと**豆腐にはならず字形だけが
中国語になる**。検査を通り抜けるので `references/quality.md` の該当節を読むこと。

#### 必須素材が手元に無いとき

黙って省略しない。どちらかを実行し、**代替で進めたことを必ず伝える**。

- **ロゴが無い** → ユーザーに求める。ロゴはブランドの資産で、こちらで勝手に決めるものではない。
  どうしても先に進める必要があるなら `scripts/build_logo.py` で仮のロックアップを組めるが、
  それが仮であることを明示する
- **背景が無い** → 生成する。画像生成AIに任せる場合のプロンプト指針は `references/recipes.md`。
  それも使えないなら `--bg-color` にCSSグラデーションを渡す。実用に足るが、これも仮扱いにする

#### 任意の素材をこちらで用意する場合

ユーザーから「任せる」「いい感じに」と指示があったときだけ、選定または生成する。
勝手に足さない。指定されたものを上書きしない。

**フォントを選ぶとき**

- ブランドフォントがあるなら必ずそれを使う。無いときだけ選ぶ
- 見出しはウェイト700以上。細字は縮小表示で最初に潰れる
- 明朝は品が出るが縮小に弱い。SNSに流すものはゴシックを選ぶ
- 実際に環境にあるものから選ぶ（`fc-list` で確認）。存在しないフォント名を提案しない

**キャッチコピーを書くとき**

画像が運べる情報は一つだけで、それは「何のサービスか」。サイト名はロゴとバッジで既に出ているので、
そこを繰り返すと1行を無駄にする。

- 1行、20〜30文字。20文字なら Slack の表示幅でも読み切れる
- 「誰が」「何を」「どうなる」のうち2つ以上を入れる
- 体言止めより述語で終えるほうが読み手が動く
- **3案出してユーザーに選ばせる。** 1案だけ出して押し切らない。
  キャッチコピーは好みの幅が大きく、こちらの1案が当たる確率は低い

**装飾を選ぶとき**

装飾は縮小表示で最初に消える。間を作り視線を止める、以上の仕事はさせない。
情報量が多いときは `none` のままにするほうが良い。

| style | 見え方 | 向く場面 |
|---|---|---|
| `none` | 装飾なし（既定） | 情報量が多いとき、迷ったとき |
| `rule` | 短い太線 | 汎用。アクセントカラーを効かせたいとき |
| `line` | 中央が濃い細線 | 上品に間を作りたいとき |
| `dots` | 三点 | 軽い印象。ブログ、カジュアル |
| `diamond` | 線＋菱形 | 高級感。占い、美容、士業 |
| `star` | 線＋四芒星 | 同上。より装飾的 |

すべてインラインSVGの図形で描くのでフォントに依存しない。
`◆` `✦` のような約物を**文字として**置くとグリフ依存になり、
フォントによっては豆腐になる。装飾でその事故を起こす価値はない。

### 3. ビルドする

```bash
python3 scripts/build_image.py \
  --preset ogp \
  --title "生成AIを使った受託開発の見積り精度を、稟議まで通る粒度で標準化する" \
  --meta "Mediowl Tech Blog ・ 2026.08.25" \
  --badge "TECH" \
  --bg bg.jpg --logo logo.svg \
  --out ogp.png
```

主なオプション（`--help` に全部ある）:

- `--layout standard|centered|strip` — 既定は縦横比から自動選択。横長は `standard`、
  正方形・縦長は `centered`、極端に横長な帯は `strip`
- `--accent` `--fg` `--bg-color` `--meta-color` — 色
- `--overlay 0.0-1.0` — 背景を沈める膜の濃さ。背景写真が明るくて文字が読みにくいときに上げる
- `--badge` `--cta` — カテゴリラベル、ボタン風のCTA
- `--divider none|rule|line|dots|diamond|star` — 見出しの上に置く区切り装飾。
  すべてSVG図形なのでフォント非依存。選び方は上の「装飾を選ぶとき」
- `--sub` — 見出しの**直下**に置くサブコピー。`--meta` は下端の情報行（日付・媒体名）で役割が違う
- タイトルに**改行文字を入れると、その位置で改行される**。日本語は単語の区切りが無いため
  ブラウザがほぼ任意の位置で折り返し、「無料診断は／じめました」のような語中改行が起きる。
  避けたい箇所があるときは改行を明示するのが唯一確実な方法（空白を入れるだけでは効かない）
- `--extra-css style.css` — CSSを追記してブランドに寄せる。既定のテンプレを壊さずに調整できる
- `--scale` — **掲載面の表示幅とディスプレイの倍率で決める**。判断基準は下の表。
  「とりあえず1」でも「とりあえず2」でもなく、`表示CSS幅 × デバイスピクセル比` が
  画像の画素数を超えていないかで決まる

### 3.5 解像度が足りているか確認する

Retinaなどの高精細ディスプレイは、CSS上の1pxを物理2pxで描く。
**画像の画素数が `表示CSS幅 × デバイスピクセル比` を下回ると、OSが拡大して表示するため
そこで初めて滲む。** 実測ではこの拡大で鋭度が 0.71 → 0.39 まで落ちた。

| 掲載面 | 表示CSS幅の目安 | Retinaで必要な画素幅 | 判断 |
|---|---|---|---|
| X / Slack / LINE のリンク展開 | 300〜500px | 600〜1000px | `ogp` 1200px で足りる。`--scale 1` |
| 記事内のアイキャッチ（本文幅） | 700〜800px | 1400〜1600px | 1200pxでは不足。`--scale 2` |
| サイト全幅のヒーロー / スライダー | 1440px前後 | **2880px** | `slider` 1920pxでは不足。**`--scale 2`** |
| YouTube サムネイル一覧 | 168〜360px | 336〜720px | `thumbnail` 1280px で余裕。`--scale 1` |

**OGPは1xで足りるが、サイト内で大きく表示するものは2xが必要**というのが要点。
SNSのリンク展開は表示枠が小さいので、1200pxでも物理ピクセルを上回っている。

これは判読性（文字が小さすぎて読めない）とは別の軸なので混同しないこと。
- **鮮明さ**: 画素数が足りない → 解像度を上げれば直る（この節）
- **判読性**: 表示幅に対して文字が小さい → 解像度を上げても直らない。文字を大きくする
  （`references/presets.md`）

### 4. 出力を必ず自分の目で見る

`Read` ツールで生成したPNGを開いて確認する。数値で裏を取りたいときは
`scripts/measure_quality.py` にかける（エッジ鋭度が0.65未満ならリサイズか
非可逆圧縮が混入している。判定基準は `references/quality.md`）。スクリプトの判定が `OK` でも、
背景と文字のコントラスト、トリミング位置、ロゴの視認性は人間（とあなた）の目でしか判断できない。
複数枚作ったときは1枚のコンタクトシートにまとめてから見ると早い。

## スクリプトが持つ3つの安全装置

これは「黙って壊れた画像を出す」のを防ぐためのもの。警告が出たまま納品してはいけない。

1. **グリフ検査** — 描く前に fontTools でフォントの文字カバレッジを検査する。
   タイトルに含まれる文字のグリフが無ければ、画像を作らずにエラーで止まり、
   足りない文字を列挙する。これが □□□ 事故を原理的に防ぐ仕組み。

2. **タイトルの自動縮小** — 収まる最大サイズを二分探索で決める。
   手でフォントサイズや改行位置を決めると、タイトルの長さが変わった瞬間に破綻する。
   だから記事ごとに文字数が変わっても同じテンプレで通る。

3. **はみ出し再検査** — 縮小後もはみ出していれば `overflow` として異常終了する（exit code 2）。
   `shrunk-to-min` は最小サイズまで縮んだという警告で、文字数を削るサインとして扱う。

## よくある落とし穴

- **JPEG/WebPで保存しない。** 文字のエッジに圧縮ノイズが出る。スクリプトはPNG固定にしてある。
  容量が問題なら `pngquant` などで減色する（文字の輪郭は保たれる）。
- **後からリサイズしない。** 生成後に別サイズが必要になったら、その寸法で作り直す。
  縮小は情報が落ちて戻らないし、拡大はボケるだけ。
- **小さい文字・細字・薄いグレーを使わない。** 実測でこの3条件が最も潰れやすい。
  SNSのプレビューはさらに縮小されるので、主要コピーは実寸40px以上を確保する。
- **背景に文字を含む生成画像を使わない。** 背景の文字は修正できず、こちらで描いた文字と競合する。

## 参照ファイル

- `references/presets.md` — 用途別の寸法一覧、SNS側の表示縮小、レイアウト選択の基準
- `references/quality.md` — なぜ劣化するのかの原理と、実測で確認した数値。
  想定外の荒れ方をしたときの切り分けに使う
- `references/recipes.md` — バッチ（`--spec`）の書式、背景生成のプロンプト指針、
  ブランド適用、テンプレ拡張の方法
- `references/logo.md` — 横型 / 縦型ロゴの作り方、推奨表示高さ、書き出しサイズ、
  反転版やfaviconなど実務で必ず要求される派生
- `scripts/build_logo.py` — ロゴロックアップのビルダー（SVG＋透過PNG）
- `scripts/measure_quality.py` — エッジ鋭度と実効字高の測定器。納品前の確認に使う
