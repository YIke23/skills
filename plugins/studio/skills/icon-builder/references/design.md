# 16pxで生き残る意匠

アイコンが失敗する原因はほぼ1つに集約される。**大きい状態で設計して、小さい状態で検品しない。**
16×16 は 256ピクセルしかない。ここで残るものだけが意匠として機能する。

## マスターSVGの書き方

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 512 512">
  <style>
    .plate { fill: #1c56d6 }
    .mark  { fill: #ffffff }
    @media (prefers-color-scheme: dark) { .plate { fill: #5b8def } }
  </style>
  <rect class="plate" width="512" height="512" rx="112"/>
  <path class="mark" d="M128 368V144h56l72 116 72-116h56v224h-52V232l-60 96h-32l-60-96v136z"/>
</svg>
```

- **`viewBox="0 0 512 512"` 固定。** ルートに `width`/`height` は書かない（スクリプトが落とす）。
  512を基準にすると「線幅32以上」がそのまま読める数字になる
- ダークモード対応は**SVG内の `<style>`** に書く。外部CSSは読み込まれない
- 文字は `<text>` のままでよい。`build_icons.py --font` がパスに変換する。
  ただし tspan や入れ子は未対応なので、1行1要素で書く
- `<image>`（ラスタ埋め込み）、`<script>`、外部URL参照は使わない。
  埋め込みラスタはSVGにする意味を消し、Base64で約1.37倍に膨らむ

## 数値の根拠

512pxのキャンバス上で線幅を変えて16pxに縮小し、白背景に対するコントラスト比を実測した結果:

| 512上の線幅 | 16px換算 | コントラスト比 | 判定 |
|---|---|---|---|
| 8 | 0.25px | 1.4:1 | 消える |
| 16 | 0.50px | 2.1:1 | 読めない |
| 24 | 0.75px | 3.3:1 | WCAG下限ぎりぎり |
| **32** | **1.00px** | **5.2:1** | **実用下限** |
| 48 | 1.50px | 12.4:1 | 良好 |
| 64 | 2.00px | 19.4:1 | 堅牢 |

**線・要素の太さは32単位（1/16）以上、推奨は51〜64単位（1/10〜1/8）。**
WCAG 2.1 SC 1.4.11 は文字を伴わない単体アイコンに3:1を求めており、24単位がその境界にあたる。

**隙間も同じ規則に従う。** 16px換算で1pxを切ると、隣接する図形がアンチエイリアスで
繋がって団子になる。塗りの太さだけ気にして隙間を詰めると同じ場所で失敗する。

## 要素数

判別できる要素は**2〜3個まで**。同心円、細い枠線、小さな抜き文字、グラデーションの階調は
16pxで全部消える。文字を載せるなら**1〜2字**。3文字以上は必ず潰れる。

## コントラストは両方のタブで

faviconはブラウザのタブに乗り、タブの地色はテーマで変わる（明るい側は白、暗い側は #202124 前後）。
**中間明度の単色ロゴは両方で失敗する。** 対処は2つ。

1. SVG内で `prefers-color-scheme` を使って色を切り替える（本命）
2. 明暗どちらでも3:1を確保できる色にする、またはプレート型にして地色ごと持ち込む

プレート型（角丸の四角に白抜き）が強いのはこれが理由で、タブの地色に依存しなくなる。

## 切り抜きへの耐性

| 面 | 形 | 守るべき範囲 |
|---|---|---|
| iOSホーム画面 | 角丸（半径22.37%） | 四隅に情報を置かない |
| Androidホーム画面 | 端末依存（円/角丸/四角） | **中央の直径409px（512換算）の円**の内側 |
| Android adaptive前景 | OEM依存 | 108dp中の**中央66dp**の正方形 |

SNSアカウント用のアイコンは社ごとに切り抜きが違い（円と角丸四角が混在する）、
社ごとに縮尺を変えて焼き分ける必要がある。`sns-icon-builder` の担当。

`maskable` の409という数字は、W3Cの仕様が安全域を「アイコンの短辺の40%を半径とする
中央の円」と定義していることによる（512 × 40% × 2 = 409.6）。

**プレート型なら四隅が切られるのは想定内**で、守るべきはプレートの中のマークだけ。
`verify_icons.py` は画像の外周から地色を推定してプレートを地色側に回すので、
この区別を自動でやっている。

## 検証で落ちたときの直し方

| 落ちた項目 | 何が起きているか | 直し方 |
|---|---|---|
| `16px可読性` 最大コントラストが低い | 地色に溶けている | プレート型にする / 色を濃くする / `prefers-color-scheme` で反転版を用意 |
| `16px可読性` 有効面積が少ない | 線が細い、要素が小さい | 線を32単位以上に。余白を削ってマークを大きく |
| `最小線幅` | 縮小で消える太さ | 線幅を上げる。装飾のヘアラインは削除する |
| `maskable 安全域` | 中央の円からはみ出す | `--maskable-scale` を下げる。既定の `auto` は必ず収まる値を選ぶ |
| `Android 安全域` | 66dpの外に出ている | `--android-logo-dp` を下げる（48〜66の範囲） |
| `容量` 超過 | パスが多い / 写真的 | 要素を減らす。グラデーションを単色に。これは意匠の問題であって圧縮の問題ではない |
| `ダークモード指定が無い` | 暗いタブで読めない可能性 | SVGに `@media (prefers-color-scheme: dark)` を足す。プレート型なら不要な場合もある |

## プレート型を作るときは「マークだけのSVG」も用意する

プレート型（角丸の四角＋白抜きのマーク）は16pxで最も強い形だが、
**iOSとAndroidのアプリアイコンは前景と背景を別レイヤーで受け取り、システムが重ねる。**
前景に地色が入っていると二重になり、Androidのmonochromeに至ってはただの四角になる。

なので、プレート型のマスターを作ったら、**同じ座標系（`viewBox="0 0 512 512"`）で
マークだけを描いたSVGをもう1枚**用意して `--mark-svg` に渡す。プレートを消して
マークのパスだけ残せばよいので、コピーして `<rect>` を削るだけで済む。

```
master.svg       プレート + マーク   → favicon / apple-touch / maskable / App Store
master-mark.svg  マークのみ          → iOS前景レイヤー / Android adaptive前景 / monochrome
```

Webだけが対象（`--targets web,pwa`）なら不要。

## やってはいけないこと

- **ラスタ画像をトレースして終わりにしない。** アイコンは縮小前提の再設計であって、
  ロゴの縮小コピーではない。ロゴにある細部は落とす前提で描き直す
- **案を色違いで水増ししない。** 選べない。方向性の違う案を出す
- **512pxのレンダリングだけ見て決めない。** 必ず `preview_icons.py` の原寸を見る
