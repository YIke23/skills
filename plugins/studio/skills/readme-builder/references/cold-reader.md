# まっさらな読者テスト

書き手は文脈を知りすぎているので、README の欠落が読めない。README **だけ**を渡した
サブエージェントに、引き継ぐ人が最初に抱く質問を答えさせ、答えられなかった質問を欠落とみなす。

## 渡し方

Agent ツールで1体起こす。README の本文をプロンプトに貼り、**リポジトリは読ませない**。
リポジトリを読めると、README に無いことをコードから補って答えてしまい、欠落が見えなくなる。

```
あなたは明日からこのリポジトリの担当を引き継ぐエンジニアです。
手元にあるのは下の README だけで、コードも前任者もまだ見られません。

次の質問に、README の記述だけを根拠に答えてください。
README から答えられない質問には、推測せず「README からは分からない」と答えてください。
README の「関連文書」に答えが載っていそうな資料が明示されていれば、
「関連文書の〈資料名〉を見る」と答えてかまいません（資料の中身は読めません）。
一般的な慣習からの推測も禁止です。答えられた質問には、根拠にした README の見出しを添えてください。

1. これは何をするもので、いまどういう状態か（開発中・稼働中など）。開発環境と本番の URL は何か
2. どのディレクトリに何があり、何の言語・フレームワークで書かれているか
3. 手元で動かすには、何を用意して、どのコマンドを順に叩くか。成功したとどう判断するか
4. 作業はどのブランチで始め、どこへ PR を出すか。マージするとどの環境（URL）に出るか
5. 普段の開発でテスト・lint・ビルドを回すコマンドは何か
6. 環境変数の入手先、デプロイの手順、困ったときの対処は、どの資料を見ればよいか
7. AI エージェントに作業させるとき、規約はどこにあるか

最後に、README を読んで引っかかった箇所（意味が取れない、手順が飛んでいる、
用語が説明なしに出てくる）を3つまで挙げてください。

--- README ここから ---
<README の全文>
--- README ここまで ---
```

## 結果の読み方

- 「README からは分からない」 — 欠落。§2 に戻り、リポジトリかユーザーから事実を取って埋める
- 答えたが根拠の見出しが的外れ — 書いてあるが見つけられない。見出しか配置を直す
- 「関連文書の〈資料名〉を見る」 — README の役目は果たしている。その資料が実在し、中身が埋まっているかは別に確かめる
- 引っかかった箇所 — 用語の説明不足か、手順の飛び。書き足すより先に、その用語が本当に要るかを疑う

質問 3〜4 に答えられない README は、引き継ぎには使えない。ただし種類によっては
質問そのものが当てはまらない（ライブラリにデプロイ先は無い）。その場合は質問を外してよい。

質問 6 は、README に答えそのものを書く必要は無い。関連文書の表で資料を名指しできれば合格とする。
答えを README に書き足して長くするより、docs の資料を関連文書に載せる。
