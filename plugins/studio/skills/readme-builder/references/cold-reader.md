# まっさらな読者テスト

書き手は文脈を知りすぎているので、README の欠落が読めない。README **だけ**を渡した
サブエージェントに、引き継ぐ人が最初に抱く質問を答えさせ、答えられなかった質問を欠落とみなす。

## 渡し方

Agent ツールで1体起こす。README の本文をプロンプトに貼り、**リポジトリは読ませない**。
リポジトリを読めると、README に無いことをコードから補って答えてしまい、欠落が見えなくなる。

```
あなたは明日からこのリポジトリの担当を引き継ぐエンジニアです。
手元にあるのは下の README だけで、コードも前任者もまだ見られません。

次の質問に、README の記述だけを根拠に答えてください。
README から答えられない質問には、推測せず「README からは分からない」と答えてください。
一般的な慣習からの推測も禁止です。答えられた質問には、根拠にした README の見出しを添えてください。

1. これは何をするもので、誰が使っているか
2. 手元で動かすには、何を用意して、どのコマンドを順に叩くか。成功したとどう判断するか
3. 動かすのに要る秘密情報（API キーなど）はどこで手に入るか
4. 変更を本番に出すには、どのブランチに何をすればよいか
5. 本番で何かが壊れたとき、まず何を見て、誰に連絡するか
6. やってはいけない操作は何か
7. 外部サービスは何を使っていて、管理画面には誰が入れるか
8. 次に読むべき文書はどこにあるか

最後に、README を読んで引っかかった箇所（意味が取れない、手順が飛んでいる、
用語が説明なしに出てくる）を3つまで挙げてください。

--- README ここから ---
<README の全文>
--- README ここまで ---
```

## 結果の読み方

- 「README からは分からない」 — 欠落。§2 に戻り、リポジトリかユーザーから事実を取って埋める
- 答えたが根拠の見出しが的外れ — 書いてあるが見つけられない。見出しか配置を直す
- 引っかかった箇所 — 用語の説明不足か、手順の飛び。書き足すより先に、その用語が本当に要るかを疑う

質問 4〜7 に答えられない README は、引き継ぎには使えない。ただし種類によっては
質問そのものが当てはまらない（ライブラリに本番は無い）。その場合は質問を外してよい。

全部埋めようとして README が長くなりすぎたら、答えを docs/ に置いて README からリンクする。
まっさらな読者がリンクをたどって答えられれば、それで合格とする。
