# リポジトリの種類ごとの差分

`assets/template.md` は Web アプリを基準にしている。種類が違うときに、README と関連文書で足すもの・削るもの。
迷ったら「読者が最初にやりたい操作は何か」で決める。

| 種類 | 読者が最初にやりたいこと | 足す | 削る・軽くする |
|---|---|---|---|
| Web アプリ | 画面を手元で開く | 起動後に開く URL、ログイン用のテストアカウントの入手先 | — |
| API サーバー | 1本叩いてみる | 叩く例（curl 1本）、API 仕様の置き場所（OpenAPI など） | 画面の説明 |
| ライブラリ | 自分のコードから呼ぶ | インストールと最小の使用例、対応する版、公開手順（持ち主向け） | 環境とデプロイ（公開手順に置き換え） |
| CLI | 1回実行してみる | インストールと代表的な実行例、主要なオプション（全部は `--help` に任せる） | 環境とデプロイ |
| モノレポ | 自分が触る部分を探す | パッケージ一覧（名前・役割・担当）と、全体を一括で動かすコマンド | 各パッケージの詳細（各 README へ） |
| 設定・dotfiles 置き場 | 何がどこにあるか知る | 置いてあるものの一覧、反映のしかた、足し方 | セットアップ・テスト |
| モバイルアプリ | 検証端末に最新版を入れる | 関連文書に `docs/device-builds.md` と検証端末の一覧、`deployment.md` にストア提出 | はじめかたの成功の目安を「シミュレータ／実機で開く」に置き換える |
| 社外公開の OSS | 使えるか判断する | ライセンス、貢献の手順、動作例の画像 | 担当・秘密情報の置き場所（社内情報を出さない） |

## モノレポの README

ルートの README は各パッケージの README への地図にする。ルートに全部書くと、
パッケージ側の README と二重になり、片方が古びる。

## 社外公開する場合

社内向けの節（担当の個人名、Slack チャンネル、1Password の保管庫名、社内 URL）は
公開してよいか必ずユーザーに確かめる。公開 README から消した情報は docs/ ではなく
社内の場所（社内 wiki など）へ移す。docs/ も同じく公開されるため。

## モバイルアプリの README

`docs/device-builds.md`（検証端末へのビルドと更新）は、**最新版を検証端末に入れるまで**を書く資料。
ストアへの提出と審査は `docs/deployment.md` に置く。README には関連文書のリンクだけを置く。

引き継ぎで最も事故になるのはアカウントの持ち主。次の行を `docs/external-services.md` の表に必ず置く。

| 行 | 書くこと |
|---|---|
| Apple Developer Program | Account Holder（契約の名義人）。この人がいなくなると契約の更新や規約の同意ができない |
| App Store Connect | 配布や提出ができる人と、その役割 |
| Google Play Console | 所有者と、配布や提出ができる人 |
| 配布サービス（Firebase / EAS / DeployGate など） | プロジェクトのオーナー |
| 署名 | 証明書・プロビジョニングプロファイル・keystore の置き場所。**keystore を失うと Android は同じアプリとして更新できない** |

版番号の置き場所は、構成によって違う（Expo は app.json、Flutter は pubspec.yaml、
Capacitor とネイティブは build.gradle と Xcode の設定）。scan_repo.py が拾った場所を写し、
記憶で書かない。
