# リポジトリの種類ごとの差分

`assets/template.md` は Web アプリを基準にしている。種類が違うときに、足す節と削る節。
迷ったら「読者が最初にやりたい操作は何か」で決める。

| 種類 | 読者が最初にやりたいこと | 足す | 削る・軽くする |
|---|---|---|---|
| Web アプリ | 画面を手元で開く | 起動後に開く URL、ログイン用のテストアカウントの入手先 | — |
| API サーバー | 1本叩いてみる | 叩く例（curl 1本）、API 仕様の置き場所（OpenAPI など） | 画面の説明 |
| ライブラリ | 自分のコードから呼ぶ | インストールと最小の使用例、対応する版、公開手順（持ち主向け） | 環境とデプロイ（公開手順に置き換え） |
| CLI | 1回実行してみる | インストールと代表的な実行例、主要なオプション（全部は `--help` に任せる） | 環境とデプロイ |
| モノレポ | 自分が触る部分を探す | パッケージ一覧（名前・役割・担当）と、全体を一括で動かすコマンド | 各パッケージの詳細（各 README へ） |
| 設定・dotfiles 置き場 | 何がどこにあるか知る | 置いてあるものの一覧、反映のしかた、足し方 | セットアップ・テスト |
| 社外公開の OSS | 使えるか判断する | ライセンス、貢献の手順、動作例の画像 | 担当・秘密情報の置き場所（社内情報を出さない） |

## モノレポの README

ルートの README は各パッケージの README への地図にする。ルートに全部書くと、
パッケージ側の README と二重になり、片方が古びる。

## 社外公開する場合

社内向けの節（担当の個人名、Slack チャンネル、1Password の保管庫名、社内 URL）は
公開してよいか必ずユーザーに確かめる。公開 README から消した情報は docs/ ではなく
社内の場所（社内 wiki など）へ移す。docs/ も同じく公開されるため。
