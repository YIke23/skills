# リポジトリの種類ごとの差分

`assets/template.md` は Web アプリを基準にしている。種類が違うときに、README と関連文書で足すもの・削るもの。
迷ったら「読者が最初にやりたい操作は何か」で決める。

| 種類 | 読者が最初にやりたいこと | 足す | 削る・軽くする |
|---|---|---|---|
| Web アプリ | 画面を手元で開く | 起動後に開く URL、ログイン用のテストアカウントの入手先 | — |
| API サーバー | 1本叩いてみる | 叩く例（curl 1本）、API 仕様の置き場所（OpenAPI など） | 画面の説明 |
| ライブラリ | 自分のコードから呼ぶ | セットアップにインストールと最小の使用例、対応する版 | ブランチとデプロイ先のデプロイ先を公開先（npm など）に置き換える |
| CLI | 1回実行してみる | セットアップにインストールと代表的な実行例（オプションの全部は `--help` に任せる） | ブランチとデプロイ先のデプロイ先を配布先に置き換える |
| モノレポ | 自分が触る部分を探す | ディレクトリ構成をパッケージ一覧（名前・役割・言語）にし、全体を一括で動かすコマンド | 各パッケージの詳細（各 README へ） |
| 設定・dotfiles 置き場 | 何がどこにあるか知る | ディレクトリ構成に置いてあるもの、セットアップに反映のしかた | ブランチとデプロイ先、よく使うコマンド |
| モバイルアプリ | 検証端末に最新版を入れる | ディレクトリ構成に ios/・android/ とその言語、ブランチとデプロイ先にストア・配布サービス | セットアップの成功の目安を「シミュレータ／実機で開く」に置き換える |
| 社外公開の OSS | 使えるか判断する | ライセンス、貢献の手順、動作例の画像 | 社内の資料・社内 URL へのリンク（社内情報を出さない） |

## モノレポの README

ルートの README は各パッケージの README への地図にする。ルートに全部書くと、
パッケージ側の README と二重になり、片方が古びる。

## 社外公開する場合

社内向けの記述（個人名、Slack チャンネル、社内 URL、社内の資料へのリンク）は
公開してよいか必ずユーザーに確かめる。公開 README から消した情報は docs/ ではなく
社内の場所（社内 wiki など）へ移す。docs/ も同じく公開されるため。

## モバイルアプリの README

README に置くのは、ほかの種類と同じく入口の章だけ。違いは3つ。

- **ディレクトリ構成** — `ios/`・`android/` と、その言語・フレームワーク（Swift / Kotlin、Capacitor / Expo など）
- **セットアップ** — 成功の目安は「シミュレータか実機でアプリが開く」。Xcode・Android Studio・JDK の版を前提に書く
- **ブランチとデプロイ先** — デプロイ先の列に、配布サービス（TestFlight / Firebase App Distribution など）やストアを書く

検証端末への配布手順、端末の一覧、アカウントの持ち主は docs の資料に任せ、関連文書に列挙する。
版番号の置き場所など、scan_repo.py が拾った事実は記憶で書き換えない。
