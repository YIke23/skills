# meeting-deck

読み手は会議室か Zoom にいて、**あなたの話を聞きながら**この画面を見ている。
一人で黙って読む記事とは、必要なものが違う。

入力は**書き上がった .md**。中身は既に決まっているので、このスキルは何を書くかを決めない。
決めるのは見せ方だけ——どの節に何の図を入れ、何を本文から図へ移し、投影して読めるかを保証する。

## 章立ては動かさない

md の見出しの順番と粒度は、書いた人が会議の流れを考えて決めたもの。
「意思決定はこの順で説明すべき」のような型を持ち込んで並べ替えると、
**書いた人が話すつもりだった順番と、画面に出る順番がずれる。**
会議中にそれを直すことはできない。

`h2` が1節（`.panel`）になり、その順番のまま出る。見出しの文言も原則そのまま使う。
体言止めを文に直す程度の手入れは後述の範囲で認めるが、順番と粒度には触れない。

## 「図が主役」の意味

これを「全部の節に図を置く」と読むと必ず失敗する。
図にしにくい節に無理に図を置くと、**本文の箇条書きを四角で囲んだだけのもの**が出てくる。
それは図ではなく、読む量が増えただけの飾りになる。

判定はふたつ。どちらも図を描く前に答えられる。

**1. その図を入れたら、その節の本文は短くなるか。**
図は飾りではなく、文章で書くと長くなるものを引き受ける担当。
引き受けていれば、本文から消える文が必ずある。消える文が無いなら、その図は仕事をしていない。

**2. その図を指差しながら喋れるか。**
会議で図は「指す先」として使われる。「ここが今回変わるところです」と言って指せる箇所が
無い図は、聞き手にとって意味がない。

結果として、**図が入る節と入らない節が混ざる。** それでいい。
数字が主役の節は `.stats`、項目の対照が主役の節は表で見せるほうが速い。

## 工程

### Step 1 — md を読んで、当たりを付ける

`h2` を数え、節ごとの本文の字数を測り、各節が「何の形の話か」を見る。
補足素材（スプレッドシート・コードベース）が渡されていれば、この時点で開く。
数字や構成を図にするなら、**推測ではなく実物を見てから描く**必要がある。

ここで [手を止める条件](#手を止める条件) に当たっていないか確かめる。

**保存先もここで決める。** 既定は **元の .md と同じフォルダ、同じ名前で拡張子だけ `.html`**
（`docs/提案.md` → `docs/提案.html`）。書いた人が md と見比べられ、プロジェクトの中にあるので
Browser ペインでも開ける。

md が一時フォルダ（`/tmp`、`/private/tmp`、`/var/folders`、scratchpad）にある、
または会話に貼られただけでファイルが無いときは、**組み始める前に保存先を聞く。**
一時フォルダはアプリの再起動で消える。md ごと消えて、会話履歴から復元する羽目になる。
聞くときは候補を添える（「作業中のプロジェクトの `docs/` に md と HTML を置きますか」）。
組み立て用の使い捨てスクリプトは scratchpad でよいが、md と HTML は残る場所に置く。

### Step 2 — 図の割り当てを提案して、承認を取る

**ここがこのスキルの要。** 描いてから見せると、飾りの図でも「まあいいか」で通ってしまう。
描く前に表で出すと、飾りは一目で分かる。

節ごとに1行、この形で出す。

| 節 | 図の型 | 図が引き受けること | 本文から外れる文 |
|---|---|---|---|
| 2. 現状 | 4 横バー | 工程別の所要時間の差 | 「手作業では42分、半自動では18分…」の3文 |
| 3. 提案 | 6 before/after | 承認フローの変更前後 | 「現在は課長・部長の2段階で…」の2文 |
| 4. 費用 | （図なし） | — | — |

**右端の列が空の行は、その時点で飾りの図。** 提案から外すか、型を選び直す。
この列があるから、承認する側は図の良し悪しを見た目ではなく働きで判断できる。

図の型は [references/figures.md](references/figures.md) の8種から選ぶ。
横バーはラベルの長さで 4a（左）と 4b（上）を使い分ける。7字を超えるラベルが1つでもあれば 4b。
迷ったら同ファイル末尾の「型が決まらないとき」の対応表を引き直す。

承認を取ってから Step 3 に進む。

### Step 3 — 組む

[assets/skeleton.html](assets/skeleton.html) を骨格に、`<style>` へ
[assets/deck.css](assets/deck.css) の中身をそのまま貼る。外部から読み込まない。
**HTML1枚で完結させる**ので、オフラインの会議室でも、メールに添付しても開ける。

図は [references/figures.md](references/figures.md) の型を貼って文言と数値を差し替える。
座標をゼロから決め直さない。時間を溶かすうえ、viewBox を広く取りすぎて文字が縮む。

配色は `deck.css` で全組み合わせをライト/ダーク両方で測ってある。**値を勝手に変えない。**

#### 幅は固定しない。左右の余白だけがテンプレートで決まっている

`deck.css` は紙面にも本文にも最大幅を置いていない。紙面の幅は
「画面の幅 − 左右の余白（`--gutter`）× 2」で決まり、本文も図もそれを使い切る。
余白は画面 800px で 24px、1600px で 120px、2000px で 168px と、画面の幅に連れて広がる。

**本文・見出し・図・紙面に `max-width` / `width` / `min-width` を足さない。**
`padding` に `18vw` や `calc(50% - …)` を入れて余白で幅を作るのも、`--gutter` の値を
資料ごとに変えるのも、`<svg>` に `width` 属性を付けるのも同じこと。

「1行が長くて読みにくそう」と感じても足さない。投影と画面共有では画面全体が縮んで
映るので、効くのは px の絶対値ではなく画面に対する割合。本文の柱を細くすると、
広い画面では右の半分以上が空いたまま共有され、本文は短く折れて1文が4〜5行に割れる。
行の長さが気になるなら、一文を切る（[本文に手を入れてよい範囲](#本文に手を入れてよい範囲)）。

どれも `check_deck.py` が不適合で止め、`shoot_deck.py` が描画して余白を実測する。

見出しや数値が句の途中で折れたら（「月 約 / $38」）、その句だけを `<span class="nw">` で包む。
`style="white-space:nowrap"` や `&nbsp;` を直書きしない。見出しは文節で、段落は最後の行が
1〜2字にならないよう、`deck.css` が折り返しを調整している。

見た目は **Warm Paper で固定**（eli15 と同じ配色）。決まりごとは4つだけで、
どれも `deck.css` に入っている。足すときだけ気をつければいい。

- **地も文字も、端まで振り切らない**: 地は #FCFBF9、本文は #26231F。
  プロジェクタは黒が浮いて白が飛ぶので、純白×純黒（21:1）は会議室でいちばん破綻する。
  ここは 15:1 で、AA を大きく超えたまま、まぶしさだけが落ちている
- **区切りは余白で作る**: 節の切れ目は 3rem の空きと 1px の罫線。
  1画面に2つの論点が同時に映るのを防ぐのに必要なのは、線の太さではなく空きの量
- **色は1系統だけ**: 青（`--accent`）が「今回の中心・見てほしいところ」を指す。
  注意は `--warn`、取り返しがつかないことだけ `--danger`。
  投影した会議では色が指差しの代わりになるので、指す先は1つでいい
- **色面はベタで塗らない**: 強調は `--accent-soft` のような淡い地で示す。
  彩度の高い面は、投影すると本文より先に目に入って読み上げの邪魔になる

### Step 4 — 検査して、撮って、目で見る

スクリプトは、この SKILL.md があるディレクトリの `scripts/` にある
（プラグイン経由なら、この SKILL.md を読み込んだ場所の `scripts/`）。
`${CLAUDE_SKILL_DIR}` は空のことがあるので使わず、実際のパスを書く。

**4-1. 読んで検査する**

```bash
python3 <このスキルのディレクトリ>/scripts/check_deck.py 資料.html
```

終了コードは 0=問題なし / 1=警告 / 2=不適合。**2 が出たまま次へ進まない。**
見ているのは、コントラスト（ライト/ダーク両方）、図中の文字と下地の比、
画面の幅ごとの図中の文字の大きさ、幅の固定、図中の文字のはみ出し。

図中の文字の大きさがこのスキル固有で、いちばん効く。図は紙面の幅いっぱいに伸び縮みするので、
同じ `font-size` でも狭い画面では縮み、広い画面では膨らむ。800px の画面で 14px を割らないか、
2000px の画面で本文の 1.75 倍を超えないかを両側で測る。エディタでは原寸で見えるので、
どちらも目視では捕まらない。

**4-2. 撮って測る**

```bash
uv run --python 3.12 --no-project --with playwright python \
  <このスキルのディレクトリ>/scripts/shoot_deck.py 資料.html --out <scratchpad>/shots
```

画面 800 / 1600 / 2000px でページ全体を撮り、ブラウザが実際に描いた位置で測り直す。
入っている Google Chrome を使うのでブラウザのダウンロードは要らない
（無ければ playwright の Chromium、どちらも無ければ終了コード 3）。
終了コードの意味は `check_deck.py` と同じ。**2 が出たまま納品しない。**

`check_deck.py` は HTML を読むだけなので、見出しの改行の崩れや余白の具合は
「不適合 0」のまま通る。撮らないと分からないものがある。

**4-3. スクリーンショットを目で見る**

3枚とも Read で開き、次を確かめる。数字では測れないので、ここは自分の目が検査になる。

- 見出しが変な所で折れていないか（語の途中、番号だけが1行目に残る、最後の行が1〜2字）
- 左右の余白が3枚とも同じ比率で見えるか。本文が右の途中で止まっていないか
- 図中の文字が、本文と比べて小さすぎ・大きすぎに見えないか
- 図が見出しと一緒に1画面に収まっているか
- 表が潰れず、はみ出す分は横スクロールに逃げているか

直したら 4-1 からやり直す。**3枚を見ずに「検査を通った」とだけ報告しない。**

撮影が終了コード 3 で動かないときは、Browser ペインで開いて `resize_window` で
幅を 800 / 1600 / 2000 に変えながら撮る。Browser ペインは作業ディレクトリの外の
ファイル（一時フォルダ）を開けないことがある。保存先をプロジェクトの中にしておけば、
そのまま `file://` で開ける。

配色だけ測り直したいときは HTML ではなく `assets/deck.css` を直接渡す。

### Step 5 — 手を入れた箇所を報告する

保存先のパスと、ユーザーが自分で開くためのコマンド（`open 資料.html`）を示し、
**本文に手を入れた箇所を報告する**。節ごとに1行でよい。

> 2. 現状 — 4文を図に移して削除。1文（72字）を2文に分割。
> 3. 提案 — 見出しの体言止めを文に変更（「承認フローの見直し」→「承認を2段階から1段階にする」）。

**入力の .md は書き換えない。** 元原稿は書いた人のもので、差分を見比べられる状態を残す。

## 手を止める条件

次に当たったら、組み始める前に相談する。**黙って畳まない。**
どれも「どう畳むか」に書いた人の判断が要るもので、こちらが勝手に決めると
会議で説明できない資料になる。

| 症状 | なぜ止まるか |
|---|---|
| `h2` が12を超える | 会議1回では説明しきれない。分割か、当日話す範囲の指定が要る |
| 1節の本文が1,200字を超える | 1画面に収まらない。節を割るか、補足に逃がすかの判断が要る |
| 型が決まらない節が半分を超える | 図が主役という形式自体が、この内容に合っていない可能性がある |
| 数字があるのに出典が無い | 会議で最初に聞かれるのがそこ。出所を確かめてから図にする |
| md と補足素材の数字が食い違う | どちらが正かはこちらでは決められない |

相談するときは、症状と選択肢を出す。「12節あります。どうしますか」ではなく、
「12節あります。8〜10節に畳むなら、5と6は1節にまとめられそうです。どうしますか」。

## 本文に手を入れてよい範囲

読みやすさのための手入れは認められている。ただし**主張と数字と章立ては書いた人のもの**で、
そこに触れると、書いた人が知らないことが画面に出ることになる。

**手を入れてよい**

- 一文を切る（60字を超える文は、投影すると目で追えない）
- 語順を直す、読点を打ち直す
- 図に移した内容を本文から削る
- 見出しの体言止めを、言いたいことを言う文に直す
- 専門用語の初出に1行の言い換えを添える
- 箇条書きが6項目を超えていたら、表か図に移す

**手を入れてはいけない**

- 主張を変える、結論を足す
- 数字を変える、丸める、単位を揃える（丸めは判断であって整形ではない）
- 章立て——節の順番・粒度・分割
- 断定を弱める、または逆に強める
- md に無い前提や条件を補う

迷ったら、手を入れずに報告に書く。「この節の数字は単位が混在しています」と伝えるほうが、
黙って揃えるより役に立つ。

## 投影で読めるかの線

| 何を | 線 | なぜ |
|---|---|---|
| 本文 | 20px（1600px より広い画面では少しずつ大きく、2000px で 22.5px） | 画面共有は受け手側で 70〜80% に縮むことがある。17px だと 13px 相当まで落ちる |
| 紙面の幅 | 固定しない。画面の幅 − 余白 × 2 | 広い画面で右が空き、本文が短く折れるのを防ぐ |
| 左右の余白 | `--gutter`（800px で 24px、2000px で 168px） | 資料ごとに変えない。テンプレートで決めてある |
| 図中の文字 | 画面 800px で 14px 以上、2000px で本文の 1.75 倍以下 | 図は紙面に比例して伸び縮みする。狭いと消え、広いと図だけ浮く |
| 図中の font-size | 18 / 20 / 22 の3段 | この範囲なら上の両端に収まる（figures.md に早見表） |
| viewBox | 幅 960 で固定、高さ 420 まで | 幅を広げると文字が縮む。高さが 420 を超えると1画面に収まらない |
| 1節の本文 | 1,200字まで | 超えると1画面に収まらず、1画面1論点が崩れる |
| 節 | 12まで | 会議1回で説明しきれる上限 |
| 表 | `.scroll` で囲むだけ | 列の幅は `deck.css` が中身から決める。`min-width` や列ごとの `width` を自分で足さない——足すと全列が同じ幅で並び、9列の表で1行が 342px まで伸びる |
| コントラスト | 本文も図中も 4.5:1 以上 | ライトとダークの両方で満たす。片方だけ落ちる事故が出る |

数値は `check_deck.py` が測る。目で見て判断しない。
淡い色を色付きの箱に載せた瞬間に基準を割ることがあり、これは見た目では気づけない。

## 補足素材の扱い

主入力はあくまで .md。補足素材は、**図と数字を正確にするためだけに**開く。

**スプレッドシート・CSV** — 図やカードに数字を出すなら、md の数字と一致するか確かめる。
食い違ったら止めて聞く。そして、**素材に無い数字を図のために作らない。**
バーの長さを揃えたいから丸める、空いた枠を埋めたいから推定値を置く——
どちらも会議で崩れる。数字が足りないなら、その節は図にしない。

**コードベース** — 構成図を起こすなら、該当のディレクトリとエントリポイントを実際に読む。
推測で箱を並べると、その場にいるエンジニアに即座に指摘される。
読んで分からなかったことは、分からなかったと報告するほうが誠実で、次に誰が見ればいいかも分かる。

数値を図の中に書くときは、出典も図の中に置く（`.t-sub` で小さく）。
「その数字どこから？」で会議が止まるのを防げる。

## 飾りに戻りかけているサイン

組んだあとに自分の出力を見返して、次が出ていたら直す。
どれも「ちゃんと作ろう」とした結果として出るもので、悪意なく混入する。

- 図を入れたのに、その節の本文が1文字も減っていない
- 全部の節に図がある（図にしにくい節にも無理に置いた跡）
- 図の型が全部同じ（横並びのボックスばかりになっている）
- 箱の中の文字が2行以上ある。図の中は名前を置く場所で、説明を置く場所ではない
- 箱が7つ以上ある。1枚で説明できる粒度を超えている
- 図を指して「ここが」と言える箇所が無い
- 図にキャプションが無い
- `fill="#..."` の直書きがある（ダークで図だけ取り残される）
- 図中の文字が箱の枠に触れている、またはバーと重なっている（長いラベルは figures.md 4b）
- `deck.css` の後ろに `max-width` や余白の上書きを足している
- 同じページの複数のSVGで `<marker>` の `id` が重複している（2枚目以降の矢印が消える）

## 同梱物

| 置き場所 | 中身 |
|---|---|
| `assets/deck.css` | 配色と組版。`<style>` にそのまま貼る。値は測定済みで、変えない |
| `assets/skeleton.html` | 骨格。節の索引と、← → での節移動（クリッカーが送るキー） |
| `references/figures.md` | 図の型8種（横バーは2通り）。貼って文言と数値を差し替えて使う |
| `scripts/check_deck.py` | 読むだけの検査。コントラスト、図中の文字の色・大きさ・はみ出し、幅の固定 |
