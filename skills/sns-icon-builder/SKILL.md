# sns-icon-builder

## 守備範囲

**作るもの**: マスターSVG 1枚から派生させた、各SNSアカウント用の正方形アイコン。
X・YouTube・Instagram・note・LINE公式アカウント・GitHub・Slack。

**作らないもの**: favicon / PWA / iOS / Android のアイコン（`icon-builder`）、
Xヘッダーやnoteヘッダーなど横長の画像（`web-image-builder`）、意匠そのものの設計
（`icon-builder` のヒアリングと候補出しを先に通す）。

**入力はマスターSVG**。手元にPNGしか無い場合は、拡大するとボケるので `icon-builder` で
SVGとして起こし直してから来ること。

**渡されたマスターSVGは絶対に書き換えない。** 検証が落ちても直さず、何がどの面で
どう壊れるかを報告して、進めるか作り直すかをユーザーに決めてもらう。詳しくは
「検証が落ちたら」。

## 中核となる考え方

> **同じ1枚を7箇所に上げてはいけない理由は容量ではなく切り抜き形状。
> そして確認する場所は、プロフィールページではなく一覧表示。**

円で切る社（X・YouTube・Instagram・note・LINE・GitHub個人）と、角丸四角で切る社
（Slack・GitHub Organization）がある。円ではマークの**対角**が内接円に収まるところまでしか
大きくできず、角丸四角では**縦横**が収まればよい。だから同じマークでも、角丸の社のほうが
大きく載る。**角に届く意匠では実測で3割違う。** 円に収まるまで縮めた1枚をSlackに上げると
小さく見え、角丸のつもりで端まで使った1枚をXに上げると欠ける。

例外はプレート型（角丸の板に白抜き、のようにキャンバスを塗り切っている意匠）で、
これは**マスクされる前提で描かれたもの**だから、どの社でも縮めずに全面のまま焼く。
面積で自動判定するので指定は要らないが、「Slackのほうが大きく載る」という説明は
プレート型には当てはまらないので、そのまま伝えないこと。

そして、上げたあとに「誰のアカウントか分からない」となるのは必ず一覧表示のほう。
**GitHubのコミット一覧とSlackのメッセージ一覧は20px**で、faviconの16pxに迫る。
プロフィールページの大きい表示で判断すると、ここを見落とす。

## 動かし方

スクリプトは Python 3.10以上 と pillow / numpy / playwright（`--font` を使うなら
fonttools も）を要求する。この Mac の `python3` は 3.9 なので、`uv` で回す。

```bash
uv run --python 3.12 --no-project \
  --with pillow --with numpy --with playwright --with fonttools \
  python <このSKILL.mdがあるディレクトリ>/scripts/build_sns_icons.py --help
```

`${CLAUDE_SKILL_DIR}` は設定されていないので使わない。パスは実際に書くこと。
以下の手順では `python3 scripts/...` と短く書くが、**実行はすべてこの `uv run` に置き換える。**

## ワークフロー

### 0. 意匠が決まっているか確かめる

このスキルは**書き出し**が仕事で、意匠を決めるのは `icon-builder` の仕事。
まだ形が決まっていないなら、先に `icon-builder` のヒアリングと候補出し
（`preview_icons.py` の16px原寸比較）を通す。順番を逆にすると、
7社ぶん焼いてから描き直すことになる。

聞くのはこの3つだけ。

| 項目 | なぜ聞くか |
|---|---|
| **マスターSVGの場所** | 無ければここで止まる。PNGしか無いなら `icon-builder` へ戻す |
| **地色**（HEX） | SNSは全社が透過の扱いを明記していないので必ず塗る。意匠がプレート型なら板と同じ色 |
| **GitHubは個人かOrganizationか** | 切り抜きが円か角丸四角かが変わる。ここだけ分岐する |

上げる先が7社すべてとは限らない。使っていないサービスは `--platforms` で外す。

### 1. 書き出す

```bash
python3 scripts/build_sns_icons.py \
  --svg master.svg --out dist \
  --pad-bg "#1c56d6" \
  --platforms x,youtube,instagram,note,line,github,slack \
  --github-account user
```

- `--pad-bg` は**地色**。透過のまま上げると、白で合成する社と黒で合成する社があり、
  ライト/ダークで破綻する。**透過の図案に、その図案と同じ色を指定すると真っ平らな板になる**
  （スクリプトが検出して止める）
- `--github-account org` で GitHub を角丸四角として焼く
- `--font` は SVG内に `<text>` が残っているときだけ。焼き上がったPNGは一見正常なので、
  フォントが解決できていないことに気づけない。それを防ぐために止めている

ファイル名がそのまま上げ先になる（`x-400.png` / `slack-512.png`）。
**ディレクトリで分けないのは、上げ先を間違えるのが一番多い事故だから。**

容量が上限を超えたら、PNG →（pngquantがあれば）減色PNG → JPEG の順に落ちる。
JPEGを最後にするのは、輪郭に圧縮ノイズが出るから。アイコンは輪郭が全て。

### 2. 検証する

```bash
python3 scripts/verify_sns_icons.py --dist dist
```

サービスごとに、**そのサービスの最小表示まで実際に縮めて**コントラスト・最小線幅・
マークの実寸を測り、切り抜き形状の安全域からインクがはみ出していないかを画素で数える。
容量上限と透過の有無も見る。終了コードは 0=問題なし / 1=警告 / 2=不適合。

いちばんよく落ちるのは**最小線幅**。512キャンバスで線を32単位（1/16）以上にする、という
icon-builder の原則がそのまま効く。20px表示で1px未満になる線は消えるので、
GitHub と Slack では「512上で25単位以上」が実質の下限になる。報告するときは
この換算をそのまま添えると、直すか進めるかの判断が1往復で済む。

**警告を残したまま黙って渡さない。** どの警告も「その画面で見え方が壊れる」という意味で、
出力ファイルの見た目からは分からないから機械で見ている。

同じ意匠でも、サービスによって合否が割れることがある。YouTube（48px）は通るが
GitHub（20px）で落ちる、はよくある。20pxで読めない形は、他の社でも一覧表示では
読めていないので、「GitHubだけ諦める」は解決になっていない。

### 検証が落ちたら — マスターSVGは直さない

**入力されたマスターSVGは絶対。** 線を太らせる、要素を減らす、色を変える——どれも
やらない。頼まれたのは書き出しであって描き直しではないし、そのアイコンは名刺・スライド・
サイトにも既に載っているかもしれない。ここで勝手に形を変えると、SNSだけ違う絵になる。

やることは**報告して判断を仰ぐ**こと。そのうえで「このまま進める」か「SVGを直す」かを
決めるのはユーザーで、こちらではない。だから報告には、決めるのに要る材料を全部入れる。

> **GitHub と Slack で線が消えます。**
>
> この2社の最小表示は20px（GitHubはコミット一覧・blameの行頭、Slackはメッセージ一覧の
> コンパクト表示）です。マスターの線幅は512キャンバス上で14単位で、20pxまで縮めると
> **0.75px** になります。1px未満の線は描画時に飛びます。
>
> - **影響を受ける面**: GitHub(20px) / Slack(20px) が不適合。X・Instagram(32px)、
>   note(40px) は1.00〜1.25pxで警告、YouTube・LINE(48px) は問題なし
> - **このまま進める場合**: 7枚とも書き出し済みなのでそのまま上げられます。
>   一覧表示では緑の丸に見えます（`preview.png` の20px原寸で確認できます）
> - **SVGを直す場合**: 線を32単位以上にすると20pxで1.5px確保できます。
>   3本のままだと隣と融合するので、2本に減らすのが要ります。`icon-builder` の担当です
>
> どちらにしますか。

ポイントは3つ。**どの面が落ちたかを面の名前で言う**（「20pxで」ではなく「コミット一覧で」）。
**そのまま進めた場合にどう見えるかを言う**——落ちた＝使えない、ではない。社内Slackだけなら
気にしない判断もありうる。**直すなら何単位必要かを数字で言う**。「太くしてください」だけでは
もう一往復になる。

書き出したPNGは消さずに残す。ユーザーが「このまま進める」を選んだとき、焼き直しが要らない。

### 3. 実寸で見せる

```bash
python3 scripts/preview_sns_icons.py --dist dist --out preview
```

`preview.html`（人が見る）と `preview.png`（`Read` で自分でも見る）が出る。
各社の切り抜き形状と最小表示の原寸が、ライトUIとダークUIに並ぶ。

**先に自分で `preview.png` を見る。** 検証が通っていても、20px原寸を見ると「これは
誰のアカウントか分からない」と判断できることがある。そのときも直すのではなく、
`preview.png` を見せたうえで「一覧ではこう見えますが、進めますか」と聞く。
機械が測れるのは線幅とコントラストまでで、形が意味を保っているかは人が見るしかない。

### 4. 渡す

`dist/UPLOAD.md` に、ファイルと置き場所と社ごとの注意が入っている。
相手が非エンジニアなら、そこに書かれたとおり伝えればよい。

**LINEは最後に回す。** 1時間に1回しか変更できないので、他社で見え方を確かめてから上げる。

## 出力されるもの

| ファイル | 寸法 | 切り抜き | 効いている制約 |
|---|---|---|---|
| `x-400.png` | 400 | 円 | 2MB |
| `youtube-800.png` | 800 | 円 | 15MB、アニメGIF不可 |
| `instagram-1080.png` | 1080 | 円 | 公式が寸法を非公開。向こうの圧縮に耐える大きさで入れる |
| `note-330.png` | 330 | 円 | 公式の推奨が330と小さい |
| `line-640.png` | 640 | 円 | 3MB、**変更は1時間に1回** |
| `github-500.png` | 500 | 円 / 角丸四角 | **1MB**（全社で最も厳しい）、最小表示20px |
| `slack-512.png` | 512 | 角丸四角 | **1MB**、512未満は受け付けない、最小表示20px |
| `UPLOAD.md` | — | — | 上げ先と社ごとの注意 |
| `build-report.json` | — | — | 各社のインク到達率と、最小表示でのマーク実寸 |

各社の根拠と、その数値が公式ヘルプ由来か実画面由来かは `references/platforms.md`。

## よくある落とし穴

- **プロフィールページの大きい表示で判断しない。** 判断は一覧表示の原寸で行う。
  `preview_sns_icons.py` がその寸法で並べる
- **1枚を7箇所に使い回さない。** 寸法が同じでも、切り抜きが違えばマークの大きさが違う。
  Slackだけアイコンが小さく見えるのはこれ
- **GitHubのOrganizationに個人用を上げない。** 角丸四角なのに円前提で詰めてあるので、
  そのぶん小さく見える
- **透過のまま上げない。** 全社が透過の扱いを明記していない。白で合成する社と
  黒で合成する社があり、どちらに転ぶか制御できない
- **地色を白（や、ほぼ白）にするときは意図してそうする。** ライトUIのタイムラインで
  輪郭が消え、マークだけが宙に浮く。検証が警告を出すので、意図しているかどうかだけ確認する
- **`--pad-bg` にマークと同じ色を渡さない。** 合成後が無地の板になる。ファイルは
  正常に見えるので、上げてから気づく類の事故。スクリプトが面積を測って止める
- **LINEを先に上げない。** 1時間に1回しか変えられない。他社で確かめてから最後に回す
- **マスターSVGを勝手に直さない。** 512キャンバスで32単位未満の線は GitHub/Slack の
  20px表示で消えるが、それは報告する事実であって、こちらで太らせてよい理由ではない。
  そのアイコンは他の場所にも既に載っている可能性がある
- **「落ちた＝使えない」と決めつけない。** 社内Slackだけ、フォロワーが少ないうちは形より
  速度、という判断はありうる。判断材料を出すところまでがこちらの仕事
- **ラスタ画像から作らない。** PNGのロゴを拡大すると全社ぶんボケる。
  元がラスタしか無いなら `icon-builder` でSVGとして設計し直す

## 参照ファイル

- `references/platforms.md` — 各社の実寸・容量・切り抜き形状・最小表示と、その出典
- `scripts/platforms.py` — 仕様表の本体。build / preview / verify / UPLOAD.md の唯一の出所
- `scripts/build_sns_icons.py` — マスター1枚から各社ぶんを焼き分ける
- `scripts/verify_sns_icons.py` — 各社の制約を機械的に検査する
- `scripts/preview_sns_icons.py` — 各社の切り抜き形状と最小表示の原寸で並べる
- `scripts/snslib.py` — 3本が共有する土台（ラスタライズ、インクの到達距離、容量調整）
