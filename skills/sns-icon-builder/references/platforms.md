# 各SNSの仕様と、その数字がどこから来たか

数値の正は `scripts/platforms.py`。ここはその根拠と、更新するときにどこを引き直せばいいかを書く。

## 一覧

| サービス | 書き出す寸法 | 容量上限 | 形式 | 切り抜き | 最小表示 |
|---|---|---|---|---|---|
| X (Twitter) | 400×400 | 2MB | PNG / JPEG / GIF | 円 | 32px（タイムラインの返信ツリー） |
| YouTube | 800×800 | 15MB | PNG / JPEG / GIF / BMP | 円 | 48px（動画下のコメント欄） |
| Instagram | 1080×1080 | 8MB | PNG / JPEG | 円 | 32px（フィード投稿のヘッダー） |
| note | 330×330 | 10MB | PNG / JPEG / GIF | 円 | 40px（記事一覧のクリエイター名の横） |
| LINE公式アカウント | 640×640 | 3MB | PNG / JPEG | 円 | 48px（トークリスト） |
| GitHub | 500×500 | **1MB** | PNG / JPEG / GIF | 個人=円 / **Organization=角丸四角** | **20px**（コミット一覧・blame） |
| Slack | 512×512 | **1MB** | PNG / JPEG / GIF / BMP | **角丸四角** | **20px**（メッセージ一覧のコンパクト表示） |

`platforms.py` は各項目に `source` を持っている。

- `doc` — 公式ヘルプに明記がある。更新時は各社の公式ヘルプを引き直す
- `ui` — 公式に記載が無く、実際の画面を見て決めた値。**切り抜き形状と最小表示が全部これ**
- `guess` — 公式が非公開で、実務の相場から置いた値。Instagram の1080だけ

出典: X Help / YouTube Help 10456525 / note ヘルプ / LINEヤフー for Business /
GitHub Docs / Slack Help（いずれも各社公式ヘルプ）

## なぜ1枚で済ませないのか

容量ではない。**切り抜かれる形が社ごとに違う**からで、しかもその違いは
「四隅が切れるかどうか」ではなく「マークをどこまで大きく載せられるか」に出る。

円で切る社では、マークの**対角**が内接円に収まるところまでしか大きくできない。
角丸四角で切る社では**縦横**が収まればよく、同じマークがそのぶん大きく載る。
角に届く意匠ほど差が開き、実測で3割違う。

`scripts/build_sns_icons.py` は外接矩形ではなく**実際のインク画素**で中心からの距離を測る。
矩形の角で測ると、丸いマークや菱形のマークを、実際には切れないのに縮めてしまう。

| 切り抜き | 効く距離 | 書き出し時に収める範囲 |
|---|---|---|
| 円 | 中心からの直線距離（対角が効く） | 半径の92% |
| 角丸四角 | 中心からの縦横距離 | 半辺の90% |

角丸率は iOS のアイコンや Slack と同じ 22% 前後を想定している。中央90%の正方形に
収めれば角に当たらない。

### プレート型は縮めない

キャンバスを塗り切っている意匠（角丸の板に白抜き、など）は、**マスクされる前提で
設計されたもの**なので全面のまま焼く。縮めると地色の板の上に板が載った入れ子に見える。
`build_sns_icons.py` は面積で自動判定する（角丸矩形96% / 円78% / 文字だけ15% と、
きれいに分かれる）。プレート型では `--pad-bg` に**板と同じ色**を渡すと、四隅の処理が
自然になる。

## 最小表示がこのスキルの本題

アイコンを確認する場所を間違えるのが、いちばん多い事故。プロフィールページの大きい表示で
「よく見える」と判断して上げ、あとから一覧表示で誰のアカウントか分からないことに気づく。

**GitHub のコミット一覧と Slack のメッセージ一覧は20px。** favicon の16pxに迫る。
ここで読めるかどうかが、その意匠を採用できるかとほぼ同義になる。

`verify_sns_icons.py` はサービスごとに、そのサービスの最小表示まで実際に縮めて

- 地色とのコントラスト（3:1未満なら塗り潰しに見える）
- 最小線幅（その寸法で1px未満なら線が消える）
- マークの実寸（表示寸法の45%未満なら小さすぎる）

を測る。目視で悩まなくてよい。

## 地色とUIの背景

favicon と違って、アバターは**切り抜かれて背景の上に載る**。地色が白に近いと、
ライトUIのタイムラインでは輪郭が消えてマークだけが宙に浮く。ダークUIでも同じことが
反対側で起きる。

`verify_sns_icons.py` は地色と #ffffff / #151618 のコントラストを測り、1.25:1 を切ったら
警告する。意図してそうしている（白地の丸いアイコン）なら無視してよい警告だが、
気づかずにそうなっているケースのほうが多い。

## 1枚で賄えないもの

ヘッダー・バナーは正方形ではないので、このスキルの守備範囲外。`web-image-builder` で作る。

| 用途 | 寸法 |
|---|---|
| X ヘッダー | 1500×500（上下60pxが環境により切れる） |
| note クリエイターページ ヘッダー | 1280×670（高精細なら1920×1006） |
| YouTube バナー | 2560×1440（セーフエリア 1235×338）、6MB以下 |
| LINE 背景画像 | 比率 2:1、10MB未満 |

## 運用上の注意

- **LINE公式アカウントのアイコン変更は1時間に1回まで。** 出し直しが効かないので、
  他社で見え方を確かめてから最後に回す
- **YouTubeはアニメーションGIF不可。** 全社で動くアイコンに統一することはできない
- **GitHub と Slack の1MB** が全社で最も厳しい。`build_sns_icons.py` は
  PNG →（pngquantがあれば）減色PNG → JPEG の順に落とす。JPEGを最後にするのは、
  輪郭に圧縮ノイズが出るから。アイコンは輪郭が全てなので、色数を削るほうが損失が小さい
- **GitHub Organization は角丸四角**。個人アカウントと同じファイルを上げると、
  円前提で詰めたぶん小さく見える。`--github-account org` で焼き直す
- **Instagram はアプリからでもWebからでも変更できる**が、アプリ側は端末の写真アプリを
  経由するので、AirDrop などでPNGを端末へ渡す必要がある
